## 4. 튜링 (Turing) — 제품

### 문제 정의
AI는 도입 초기엔 잘 작동하지만 **운영환경이 변하면 구조적·기술적으로 성능열화를 겪는다.**
핵심 메시지: *"AI 문제는 고객이 인지하기 전에 이미 발생하고 있다."*

기존 업계 방식은 사후 대응(reactive) — 고객 클레임 → 담당자 인지 → 인력 투입 → 수동 수정 → 반복.
늦은 감지, 인건비 기반 비용 증가, 확장성 제한.

### 성능열화가 발생하는 6개 축
1. **기업 대내외 환경 변화** — Concept Shift. RLHF 탓에 모르는 질문에도 그럴듯한 오답을 내고, 사용자가 못 알아채면 AI가 오답을 정답으로 인지 → 데이터 분포 붕괴
2. **기업 업무 프로세스 변화** — 확률적 추론 기반이라 낯설고 복잡한 업무일수록 확신도가 낮아짐 (코딩 AI를 의료 AI로 쓰는 격)
3. **사용자 담당업무 변화** — 최초 학습 데이터 / AI 자기생성 데이터 / 신규 주입 데이터가 뒤섞여 **모델 붕괴**, 환각 심화, 토큰 과다 소비
4. **업무 보조도구 변화** — Slack·Github·Gmail 등 외부 도구의 출력 형식/프로토콜/인코딩이 바뀌면 AI가 스스로 교정 못 함
5. **AI 의존도 변화** — 장기기억 한계 + 자기칭찬(Self-praise) 구조 → Drift
6. **AI 사용자 변화** — 같은 의도라도 말투 차이에 민감 (Prompt Brittleness) → 표현, 나아가 내용까지 달라짐

### 파이프라인 — 5개 AI Agent 순환 루프
실시간으로 동작하며 평가 → 감지 → 진단 → 계획 → 복구를 자동으로 돈다.

| # | Agent | 핵심 기술 |
|---|---|---|
| 1 | **AI평가** | 운영 대상 AI를 프로파일링해 **481개 평가지표 라이브러리**(범용 180 / Concept 120 / 도메인특화 95 / 과업별 60 / Evaluator특화 26)에서 최적 지표 선별. 기존 지표로 부족하면 신규 지표를 자동 생성 → 타당성 검증 통과분만 채택 |
| 2 | **열화감지** | 로그 실시간 분석. **BOCPD**로 변화 시점, **KL Divergence·PSI·바서슈타인 거리**로 입력 분포 변화율, **CUSUM**으로 지속성 → 심각성 점수. Threshold 초과 시 다음 단계 |
| 3 | **원인진단** | 성능저하 시점부터 시간 역순 추적. 핵심은 **반사실적 추론** — 열화가 없었을 경우를 시뮬레이션해 원인 후보 영향력을 확률로 환산 ("입력 분포 변화가 78% 원인") |
| 4 | **복구플래닝** | 프롬프트 보정 / RAG 갱신 / 임베딩 재학습 / 캐시 무효화 등 전략 수립. **몬테카를로·Agent-based 시뮬레이션**으로 사전 효과 검증 + 비용·시간·복잡도 비교해 우선순위 결정 |
| 5 | **열화복구** | **AST 호환성 검증** + 통계적 검증. 하나라도 실패하면 4단계로 회귀. **Canary Deployment 5단계** 점진 적용 + Guardrail 위반 시 자동 롤백. 롤백 시 최대 트래픽 1%로 제한 → 사용자는 복구를 인지 못 함 |

### AI Harness (보안)
Multi-Agent의 모든 행위를 통제. Safety Guardrail이 입출력단에서 민감정보 **마스킹(Redaction)** 을 실시간 수행해 무단유출을 구조적으로 차단.

### 연구개발 목표
5개 Agent + AI Harness에 걸친 **12개 정량 지표** (예: 열화원인 진단오차용 Severity MAE, 대응방안 정확도용 β-Recall).
SOTA 논문 수준 엄격성 — Multi-Seed Replication, 95% 신뢰구간, p<0.01, OpenAI·Microsoft 벤치마크 및 HarmBench 기반 데이터셋.

### 차별성
경쟁사는 평가·관측·보안을 **개별 계층**으로 다루지만, 인트는 **평가부터 복구까지 하나의 순환 루프로 통합**했고 특허를 출원했다. 고객사가 늘수록 데이터가 축적되어 성능이 향상되는 구조 → 후발 주자 진입 장벽.

## 10. 홈페이지 카피 작성 시 주의

1. **TIPS를 전면에 두지 말 것.** 튜링의 R&D 자금원이자 검증 트랙일 뿐, 회사의 정체성이 아니다.
2. **개발사 + 운영사라는 이중 정체성**이 차별점이다. "AI 만들어 드립니다"도, "모니터링 툴입니다"도 둘 다 반쪽이다.
3. **실적은 구체적 고유명사로.** LG CNS Career Lens 현업 운영, 더존 EMR 시범 적용 같은 사실이 가장 강한 카피다.
4. 아직 **프로토타입/개발 중**인 항목(히포크랏랩스, STEPI 튜링 통합)을 완료된 것처럼 쓰지 말 것.
5. 미래 매출·목표 수치(443억, 517조 등)는 투자 문서용이다. 공개 홈페이지에 그대로 올릴 값이 아니다.
6. **"변화에 적응하는 기업용 AI" / "변화적응형 AI"는 홈페이지 카피·메타데이터에 쓰지 않는다.**
   발표 스크립트의 표현이지 확인된 사실이 아니다(§3 ②의 이름도 화면에서는 "운영 자동화 내장 AI 구축"으로 적는다).
   회사 소개는 §1의 한 줄 정의를 담백하게 풀어 쓴다.
6. 5개 Agent 이름은 대외적으로는 [product.ts](../src/entities/product/model/product.ts)의 쉬운 표현("매일 점검합니다" 등)을 쓰고, 기술 용어(BOCPD, 반사실적 추론)는 기술 소개 섹션에 한정한다.

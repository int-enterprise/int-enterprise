# 모바일 디자인 최적화

이 사이트의 방문자 다수는 휴대폰으로 본다. 그런데 작업은 대부분 1440px에서 이뤄진다.
그래서 **모바일은 언제나 나중에 발견되는 문제**다. 이 스킬은 그 순서를 뒤집는다.

## 0. 대전제 — 축소가 아니라 재구성

모바일은 데스크톱을 줄인 것이 아니다. **폭이 줄면 위계가 달라진다.**

- 데스크톱에서 좌우로 나란하던 것은 모바일에서 **위아래 순서**가 된다.
  그러면 "무엇을 먼저 보여 줄지"를 다시 정해야 한다. 왼쪽이 항상 위가 아니다.
- 데스크톱에서 한 화면에 들어오던 것이 모바일에선 **세 번 스크롤**이 된다.
  스크롤이 길어지는 것 자체는 괜찮지만, **행동(버튼)이 화면 밖으로 밀리는 것은 안 된다.**
- 여백 80% 규칙은 유지하되, 모바일에선 **여백의 총량이 아니라 비율**로 생각한다.
  데스크톱 150px 여백을 그대로 두면 휴대폰에선 화면 하나가 통째로 빈다.

## 1. 먼저 측정한다 (눈으로 시작하지 않는다)

모바일 문제는 대부분 스크린샷으로 안 보인다. 가로 스크롤 3px, 7.8px로 찍힌 SVG 글자,
38px짜리 탭 영역은 눈으로 "좀 작네" 정도로만 읽힌다. 숫자로 뽑아야 고칠 목록이 된다.

```bash
pnpm build
PORT=3100 pnpm start                     # 포트를 먼저 비운다 (아래 3-1 참고)
node scripts/mobile-audit.mjs 390        # 기본
node scripts/mobile-audit.mjs 360        # 가장 좁은 실사용 폭도 함께
```

`scripts/mobile-audit.mjs`가 라우트별로 잡아내는 것:

| 종류 | 기준 | 왜 |
|---|---|---|
| 가로 스크롤 | `scrollWidth > 뷰포트` | 손가락이 좌우로 흔들리면 사이트가 고장 난 것처럼 느껴진다 |
| 화면 밖 | 요소의 `right > 뷰포트` | 잘린 카드·표는 내용이 없는 것과 같다 |
| 작은 글자 | 렌더된 `font-size < 17px` | 이 프로젝트의 타이포 최소치 |
| SVG 글자 | **viewBox 배율을 곱한** 실제 크기 < 17px | `text-[15px]`도 0.5배로 그려지면 7.5px다 |
| 작은 탭 | `a`/`button`의 렌더 크기 < 44×44 | 손가락은 커서가 아니다 |

숫자가 0이 되는 것이 목표가 아니다. **목록을 보고 무엇이 진짜 문제인지 판단**한다.

## 2. 그다음 눈으로 본다

측정은 "깨진 것"을 잡고, 스크린샷은 "이상한 것"을 잡는다. 둘 다 필요하다.

```bash
node scripts/screenshot.mjs '[{"name":"m-home","url":"http://localhost:3100/","w":390,"h":844,"full":true}]'
```

전체 페이지는 세로가 길어 축소되므로 **읽히지 않는다.** 판단이 필요한 구간은 `clip`으로 자른다.

```bash
node scripts/screenshot.mjs '[{"name":"m-hero","url":"http://localhost:3100/","w":390,"h":844,"clip":{"x":0,"y":0,"width":390,"height":900}}]'
```

전체 컷은 **구조 파악용**(섹션 순서·길이·중복), 클립은 **판단용**(글자·간격·정렬)이다.

## 3. 이 프로젝트에서 반복해서 틀리는 것

### 3-1. 서버가 겹치면 헛일한다
포트가 살아 있으면 예전 빌드가 찍힌다. 반드시 먼저 죽인다.
```bash
netstat -ano | grep -E ":3100\s+.*LISTENING" | awk '{print $5}' | sort -u | xargs -r -I{} taskkill //F //PID {}
```

### 3-2. `sm:`는 640px다 — 휴대폰은 전부 그 아래다
Tailwind 기본값을 쓰고 있다. `sm:` 이상에만 값을 주면 **휴대폰은 기본값으로 떨어진다.**
따라서 기본값(= prefix 없는 클래스)이 **모바일 값**이어야 한다. 데스크톱을 기본으로 적고
`max-sm:`으로 되돌리는 방식은 쓰지 않는다 — 순서가 뒤집혀 읽기 어렵다.

```tsx
// ✅ 모바일 먼저
<h2 className="text-[2rem] sm:text-[2.6rem]">
// ❌ 데스크톱 먼저
<h2 className="text-[2.6rem] max-sm:text-[2rem]">
```

### 3-3. 타이포 최소 17px는 모바일에서도 그대로다
`globals.css`의 `@theme`가 스케일을 덮어썼다(`text-xs` = 1.0625rem). **모바일이라고 더 줄이지 않는다.**
줄여야 할 것 같으면 글자가 아니라 **글의 양**을 줄인다.

### 3-4. SVG 안의 글자는 `text-[15px]`가 15px이 아니다
`viewBox`로 그린 그림은 컨테이너 폭에 맞춰 통째로 축소된다. 390px 화면에서 배율이 0.5면
15px 글자는 7.8px로 찍힌다. **해결책은 폰트 크기를 키우는 것이 아니다.**

- 축(성능/기간), 임계선 이름, 범례 같은 **읽어야 하는 글자는 SVG 밖 HTML로 뺀다.**
- SVG 안에 남길 글자는 `viewBox` 좌표계에서 `실제목표px ÷ 배율` 이상으로 잡는다.
- 모바일용 `viewBox`를 따로 두는 것도 방법이다(가로로 긴 그림 → 세로로 세운 그림).

### 3-5. 탭 영역 44×44
`text-sm` 링크 한 줄은 높이가 29px다. 규격을 맞추려면 글자를 키우는 게 아니라
**패딩을 준다**(`py-2 -my-2`처럼 시각적 위치는 그대로 두고 히트 영역만 넓히는 방식).
브레드크럼·"자세히 보기"·푸터 링크가 늘 여기 걸린다.

### 3-6. 가로 스크롤은 `main`에서 막는다
`html`로 올리면 루트 overflow가 뷰포트로 전파되면서 clip이 듣지 않는다(측정해서 확인했다).
`globals.css`의 `main { overflow-x: clip }` 규칙을 옮기지 않는다.

### 3-7. 표는 모바일에서 표가 아니다
3열 대조표(차별점)처럼 열이 있는 것은 좁은 화면에서 **행 단위 스택**으로 바뀌어야 한다.
`sm:grid-cols-[...]`만 주고 기본값을 비워 두면 자동으로 스택된다 — 다만 **스택됐을 때
어느 값이 무엇인지 알 수 있는지** 반드시 눈으로 확인한다(라벨이 사라지면 숫자만 남는다).

### 3-8. 이미지·3D는 세로를 잡아먹는다
히어로의 3D, 사진 띠, 콘솔 스크린샷은 데스크톱에선 옆자리를 쓰지만 모바일에선 세로를 쓴다.
**시각 요소 하나가 화면 하나를 통째로 먹으면 그 아래 내용은 없는 것과 같다.**
모바일에선 높이를 낮추거나(`h-[220px] sm:h-[380px]`), 순서를 바꾸거나(`order-*`), 감춘다.

### 3-9. 행동(버튼)은 첫 화면 안에
랜딩 히어로의 도입 문의·인재채용 버튼이 3D 아래로 밀리면 휴대폰에선 아무도 못 본다.
모바일에선 **슬로건 → 버튼 → 시각 요소** 순으로 둔다. 데스크톱 순서와 달라도 된다.

## 4. 고치는 순서

1. `mobile-audit`으로 목록을 뽑는다 (390 → 360).
2. **깨진 것부터**: 가로 스크롤 → 화면 밖 요소 → 읽히지 않는 글자 → 탭 영역.
3. **그다음 구조**: 첫 화면에 행동이 있는가, 시각 요소가 세로를 과하게 먹지 않는가,
   섹션 순서가 좁은 화면에서도 말이 되는가.
4. 고칠 때마다 해당 구간을 `clip`으로 찍어 확인한다. 코드만 보고 끝내지 않는다.
5. 마지막에 `pnpm build && pnpm lint`, 그리고 **390과 360에서 재감사**.

## 5. 하지 않는 것

- **모바일 전용 컴포넌트를 새로 만들지 않는다.** 같은 컴포넌트가 반응형으로 대응한다.
  파일이 갈라지면 한쪽만 고쳐지고 두 화면이 서로 다른 말을 하게 된다.
- **모바일에서 내용을 지우지 않는다.** 순서·크기·형식을 바꾼다. 휴대폰 사용자가
  덜 알아도 되는 것이 아니다. (단, 순수 장식은 감춰도 된다)
- **폰트를 17px 아래로 내리지 않는다.** 프로젝트 규약이고 모바일에서 더 중요하다.
- **가로 스크롤 영역을 새로 만들지 않는다.** 이미 있는 마퀴 외에 추가하지 않는다.
